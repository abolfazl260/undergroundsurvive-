# Underground Survive — Web Prototype

این پوشه نخستین نسخهٔ اجرایی وب بازی با **Phaser 3.90، TypeScript و Vite** است.

## پیش‌نیاز

- Node.js 22.12 یا جدیدتر
- npm

## اجرای محلی

از ریشهٔ مخزن:

```bash
cd game
npm install
npm run dev
```

سپس آدرس **http://localhost:5173** را در مرورگر باز کنید. گزینه‌های زیر نیز در دسترس‌اند:

```bash
npm run test
npm run build
npm run preview
```

بیلد تولیدی در `game/dist/` ساخته می‌شود و می‌توان آن را روی سرویس میزبانی فایل استاتیک منتشر کرد. نسخهٔ وب از طریق [GitHub Pages](https://abolfazl260.github.io/undergroundsurvive-/) نیز منتشر شده است؛ بیلد محلی همچنان برای توسعه استفاده می‌شود.

## اقتصاد آزمایشی برنچ
- نمایش موجودی سکه و هزینهٔ ساخت هفت اتاق، حفاری و ارتقا؛ هیچ هزینه‌ای برای عملیات غیرمجاز کسر نمی‌شود.
- موجودی اولیه ۱۵۰۰ سکه؛ امکان دریافت کمک‌هزینهٔ یک‌بارهٔ ۵۰۰ سکه برای تست.
- اعتبارسنجی موجودی و ثبت تاریخچهٔ پرداخت؛ جلوگیری از کسر سکه هنگام شکست عملیات.
- مهاجرت ذخیرهٔ قدیمی `base:v1` به `game:v2` با نگه‌داشتن نقشه و اتاق‌ها.
- اجرا با `npm run dev` روی همین برنچ؛ **GitHub Pages همچنان نسخهٔ `main` را منتشر می‌کند.**
- سند [قیمت‌ها و اقتصاد](../Docs/ECONOMY.md)

## محدودیت‌های فعلی

- هیچ‌یک از عملیات هنوز به Supabase و حساب آنلاین متصل نیست.
- **سیستم سکه و هزینه‌ها در برنچ آزمایشی `feature/coins-construction-costs` اضافه شده است؛ فقط زمان ساخت و اثر تولیدی ارتقا هنوز وجود ندارند.**
- حفاری زیرزمینی در محدودهٔ فعلی نقشه انجام می‌شود؛ گسترش عمودی با آسانسور در ایشیو #2 دنبال می‌شود.
- داده‌های اقتصادی و نقشه در `localStorage` همین مرورگر ذخیره می‌شوند و برای رقابت آنلاین معتبر نیستند.
- نسخهٔ PWA هنوز آماده نشده است. زیرساخت Capacitor برای تولید پوستهٔ Android/iOS در [مستند موبایل](MOBILE_CAPACITOR.md) آماده می‌شود.

## راهنمای معماری

- `src/modules/world`: مختصات و شبکهٔ مستقل از Phaser
- `src/modules/building`: تعریف اتاق، اعتبارسنجی و وضعیت نقشه
- `src/app`: صحنهٔ Phaser و اتصال ماژول‌ها
- `src/main.ts`: اتصال UI مرورگر و بازی

**قانون:** اطلاعات و قواعد اصلی جهان و ساختمان به Phaser وابسته نشوند. در گام بعد می‌توان آداپتورهای Supabase و ذخیرهٔ امن آنلاین را بدون بازنویسی کد رندر اضافه کرد.

## تصاویر اتاق‌ها

مدیریت تکسچرها، انتخاب نسخهٔ باکیفیت، بارگذاری فایل جایگزین و راهنمای افزودن Asset در [مستند مدیریت تصاویر](ASSETS.md) توضیح داده شده است.

شش تصویر دو‌بعدی باکیفیت در `public/assets/rooms/room-atlas-hd.webp` قرار دارند. هر فریم ۱۰۲۴×۳۴۱ پیکسل است (در مقایسه با ۱۶۰×۵۳ پیکسل نسخهٔ اولیه) و در `src/app/roomArt.ts` به نوع اتاق نگاشت می‌شود: مسکونی (۰)، فرمان و آسانسور (۱)، کارگاه (۲)، انبار (۳)، نیروگاه (۴) و معدن (۵).

`GameScene.preload` تصویر را یک‌بار بارگذاری می‌کند و `paintRooms` متناسب با ابعاد اتاق در Grid نمایش می‌دهد. سه نوع کارگاه، انبار و معدن به منوی ساخت افزوده شده‌اند. گلخانه و درمانگاه اکنون تصاویر اختصاصی خود را از `garden-medbay-atlas-hd.webp` دریافت می‌کنند (فریم‌های ۰ و ۱). در صورت مشکل بارگذاری HD، اطلس کم‌حجم `garden-medbay-atlas.webp` بارگذاری می‌شود؛ در صورت شکست هر دو، رندر رنگی برای همان نوع اتاق باقی می‌ماند.

Sprite Sheet جدید از فایل‌های اصلی با ابعاد ۲۱۷۲×۷۲۴ ساخته شده و با فرمت WebP به حدود ۴۰۸ کیلوبایت برای هر شش تصویر رسیده است. فایل قدیمی `room-atlas.webp` برای استفاده به‌عنوان نسخهٔ جایگزین در صورت خطای بارگذاری فایل HD حفظ شده است. مسیر جدید جداگانه است تا کش مرورگر فایل کم‌کیفیت قبلی را نمایش ندهد. با `setResolution(3)` برای برچسب‌ها، متن‌های روی اتاق در زوم بالا واضح‌تر می‌مانند؛ اندازهٔ نمایشی برچسب‌ها با افزایش زوم ثابت می‌ماند تا مانع مشاهدهٔ جزئیات اتاق نشود. برای اتاق‌های چندبخشی در آینده باید به‌جای کشیدن تصویر روی هر عرض دلخواه، قطعات قابل توسعهٔ جداگانه طراحی شود.

## کنترل‌های زوم و جابه‌جایی نقشه

- چرخ ماوس روی صفحهٔ بازی: بزرگ‌نمایی یا کوچک‌نمایی با حفظ محل زیر اشاره‌گر در محدودهٔ نقشه.
- موبایل یا تبلت: دو انگشت را باز یا بسته کنید (Pinch-to-zoom). حرکت مرکز دو انگشت نیز نقشه را جابه‌جا می‌کند.
- کشیدن با یک انگشت یا دکمهٔ اصلی ماوس: جابه‌جایی نقشه در زوم بیشتر از ۱۰۰٪؛ یک لمس/کلیک کوتاه همچنان ساخت و انتخاب را انجام می‌دهد.
- دکمه‌های `+`، `−` و `۱:۱` روی نقشه: کنترل دقیق زوم و بازگشت به حالت پیش‌فرض.
- محدودیت ۷۵٪ تا ۲۵۰٪ و محدودکردن حرکت دوربین به حدود نقشه، برای جلوگیری از گم‌شدن در فضای خالی.

منطق هندسی زوم در `src/app/viewport.ts` مستقل از Phaser است و تست‌های واحد دارد. زوم صرفاً تنظیم دید است و تغییری در اطلاعات ساخت‌وساز یا ذخیرهٔ بازی ایجاد نمی‌کند.

**تصاویر جدید گلخانه و درمانگاه:** دو فریم ۱۰۲۴×۳۴۱ (و نسخهٔ کم‌حجم ۱۶۰×۵۳) با همان طراحی اتاق‌های دیگر. نوشته‌های ازپیش‌ساختهٔ روی تصاویر حذف شده‌اند تا برچسب نام و سطح اتاق همچنان توسط سیستم فعلی بازی و متناسب با سطح ارتقا رندر شود. مدل داده، هزینه‌ها و ذخیرهٔ قبلی بدون تغییرند.

## راهنمای داخلی بازی

راهنمای آفلاین **از مسیر منوی اصلی یا توقف بازی ← تنظیمات ← راهنمای بازی** در دسترس است. در این صفحه ۱۵ موضوع فارسی و انگلیسی، جست‌وجوی محلی، مراحل آموزشی و فهرست اتاق‌ها با قیمت و ابعاد برگرفته از کد بازی نمایش داده می‌شود. بازکردن راهنما هیچ تغییری در وضعیت پناهگاه یا ذخیرهٔ بازی ایجاد نمی‌کند.

برای نگهداری و توسعه:
- متن‌های راهنما در `src/content/helpTopics.ts` با شناسه‌های ثابت `fa/en` قرار دارند؛ معرفی اتاق‌ها و جست‌وجو در `src/app/ui/gameHelp.ts` است.
- قیمت و ابعاد اتاق‌ها از `src/modules/economy/pricing.ts` و `src/modules/building/catalog.ts` خوانده می‌شوند؛ هنگام تغییر شروط بازشدن، متن مراحل را نیز با کد جدید همسو کنید.
- ناوبری از `src/app/gameMenu.ts`، HTML از `index.html` و استایل‌ها از `src/gameHelp.css` تأمین می‌شوند.
- تست پوشش موضوعات و فهرست اتاق‌ها در `src/app/ui/gameHelp.test.ts` است. پس از تغییر راهنما `npm run test && npm run build` اجرا شود.
- **محدودیت فعلی:** اعتبارسنج `placement.ts` هنوز مجاورت مستقیم هر اتاق جدید به اتاق دیگر را به‌عنوان قاعدهٔ مستقل اعمال نمی‌کند. این محدودیت در راهنما صادقانه توضیح داده می‌شود و تغییر آن خارج از دامنهٔ قابلیت راهنماست.
