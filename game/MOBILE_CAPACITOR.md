# نسخه موبایل با Capacitor 8

پروژهٔ وب Phaser + Vite در پوشهٔ `game/` منبع مشترک نسخهٔ مرورگر و Android است و امکان فعال‌سازی iOS را در آینده حفظ می‌کند. **هیچ کپی جداگانه‌ای از منطق بازی ساخته نمی‌شود.** دستورهای موبایل ابتدا `npm run build` را اجرا می‌کنند و بعد خروجی آفلاین `dist` را با Capacitor در WebView بومی قرار می‌دهند.

## وضعیت این مرحله

- اتصال Capacitor 8.5.3 با شناسهٔ موقت `com.undergroundsurvive.game` و نام `Underground Survive`.
- خروجی وب با `base: './'` در Vite، مناسب مسیرهای داخلی برنامه و GitHub Pages.
- اسکریپت‌های **idempotent** برای ایجاد و همگام‌سازی Android؛ دستورات iOS فقط به‌عنوان زیرساخت اختیاری برای آینده نگه داشته شده‌اند.
- اعتبارسنجی پیکربندی، نبود آدرس سرور زنده و موجودبودن دارایی‌های ضروری (از جمله داستان‌های آفلاین) در `dist`.
- Workflow مجزای دستی برای بررسی نسخهٔ وب و ساخت Debug APK؛ به‌علاوه Workflow **صرفاً دستی** برای ساخت Release APK/AAB امضاشده. **هیچ job تست یا ساخت iOS در این گردش‌کارها اجرا نمی‌شود.**
- سازگاری موجود با اندازهٔ تمام‌صفحه، `viewport-fit=cover`، safe-area و لمس/zoom حفظ می‌شود؛ کد گیم‌پلی تغییر نمی‌کند.

## پیش‌نیازها

- Node.js 22 یا جدیدتر، npm؛ اجرای `npm install` در `game/`.
- **Android**: Android Studio، Android SDK، JDK 21 و شبیه‌ساز/گوشی مناسب. Capacitor 8 از Android API 24 به بالا پشتیبانی می‌کند.
- **iOS فقط در صورت تصمیم به توسعه در آینده:** macOS و Xcode مناسب نسخهٔ Capacitor نصب‌شده؛ اکنون توسعه، تست و خروجی iOS جزو دامنهٔ پروژه نیست.
- برای انتشار واقعی APK/AAB یا IPA باید امضای برنامه، اطلاعات فروشگاه، آیکون‌ها و سیاست‌های حریم خصوصی جداگانه تنظیم شوند.

## دستورات

همهٔ دستورات از پوشهٔ `game/` اجرا می‌شوند:

```sh
npm install
npm test            # فقط تست‌های Vitest در src/
npm run mobile:test # فقط تست‌های Node در scripts/؛ رفع تداخل اجراکننده‌ها

# Android: فقط بار اول «cap add android»، دفعات بعد «cap sync android»
npm run mobile:prepare:android
npm run mobile:open:android
# یا:
npm run mobile:run:android

# iOS غیرفعال است؛ این دستورات فقط برای راه‌اندازی دستی در آینده نگه داشته شده‌اند.
# در CI و در مرحلهٔ فعلی اجرا نمی‌شوند:
# npm run mobile:prepare:ios
# npm run mobile:open:ios
```

`mobile:prepare:android` ابتدا وب را می‌سازد، با `mobile:check` بررسی می‌کند، سپس اگر پوشهٔ بومی وجود نداشته باشد آن را با نسخهٔ نصب‌شدهٔ Capacitor می‌سازد و با `cap sync` به‌روز می‌کند. هنگام خطا، خروجی همان دستور باید بررسی شود؛ اسکریپت به جای موفقیت ظاهری، با exit code غیرصفر متوقف می‌شود.

برای مشاهدهٔ بیلد سایت همچنان `npm run dev` و `npm run preview` در دسترس‌اند؛ جریان deploy-web به GitHub Pages تغییر نمی‌کند.

## خروجی‌ها و نگهداری پروژه‌های بومی

پوشه‌های `game/android/` و `game/ios/` در این مرحله **به‌صورت محلی/CI از نو ساخته می‌شوند و در Git دنبال نمی‌شوند**. این یک نقطهٔ شروع قابل بازتولید است، نه پروژهٔ بومی شخصی‌سازی‌شده و منتشرشده. اگر در فاز بعد تغییرات بومی (permission، icon، splash screen، signing، Gradle، entitlements یا Swift) انجام شوند، باید پوشه‌های بومی را از `.gitignore` خارج و در مخزن version-control کنیم؛ در غیر این صورت تولید مجدد آن‌ها تنظیمات دستی را حذف می‌کند.

Workflow آزمایشی موجود فقط Android Debug APK می‌سازد؛ Workflow جداگانهٔ جدید، تنها با اجرای دستی روی شاخهٔ main و Secretهای اختصاصی، Release APK/AAB امضاشده تولید می‌کند. در این مرحله هیچ runner مک، ساخت پوستهٔ Xcode، تست iOS یا خروجی IPA اجرا نمی‌شود. وابستگی `@capacitor/ios` و اسکریپت آماده‌سازی دستی صرفاً برای فعال‌سازی احتمالی در فاز بعد باقی می‌مانند.

## خروجی Release امضاشده (فقط دستی)

راهنمای دقیق [ساخت دستی و امن APK/AAB امضاشده](ANDROID_SIGNED_RELEASE.md) شامل ساخت keystore، تنظیم چهار GitHub Secret، انتخاب نسخه و فرمت خروجی، بررسی امضا و دریافت Artifacts است. Workflow با نام `Build signed Android release (manual only)` تنها دارای `workflow_dispatch` است؛ در push، Pull Request یا زمان‌بندی اجرا نمی‌شود. اجرای job امضا به شاخهٔ `main` محدود شده و کلید به‌هیچ‌وجه در Git ذخیره نمی‌شود. بدون پیکربندی Secretهای مالک پروژه، خروجی انتشار ساخته نخواهد شد.

## امنیت، داده و انتشار

- در `capacitor.config.json` **هیچ `server.url`، `cleartext`، پروکسی توسعه یا دسترسی HTTP عمومی وجود ندارد**؛ برنامه فایل‌های کامپایل‌شده را از بستهٔ بومی بارگذاری می‌کند.
- متن سناریو و تصاویر موجود در `public/content` همراه `dist` بسته‌بندی می‌شوند؛ JSON فقط به‌عنوان داده پردازش می‌شود، نه HTML/JS اجرایی.
- `localStorage` روی هر WebView به‌صورت محلی کار می‌کند؛ **ذخیرهٔ مرورگر یا GitHub Pages به‌صورت خودکار به برنامهٔ موبایل منتقل نمی‌شود**. برای همگام‌سازی ابری باید قابلیت جداگانه طراحی شود.
- شناسهٔ `com.undergroundsurvive.game` یک انتخاب اولیه است. قبل از انتشار در فروشگاه‌ها، مالک پروژه باید شناسهٔ رسمی و مالکیت آن را تعیین کند؛ تغییر شناسه پس از انتشار ممکن است مهاجرت کاربران را دشوار کند.
- برای تولید Release امضاشده باید keystore و Secretهای امضا تنظیم شوند؛ انتشار در Google Play همچنان نیازمند حساب توسعه‌دهنده، آماده‌سازی فهرست فروشگاه و بررسی‌های انتشار است.

## آزمون پذیرش

فقط در Android: شروع/ادامه بازی، ذخیره و بازیابی بعد از بستن برنامه، منابع و زمان‌بندی، سناریوی تصویری (از فایل محلی)، کنترل‌ها، زوم دو انگشتی، چرخش نمایشگر، safe-area، زبان فارسی/انگلیسی، حالت تمام‌صفحهٔ بازی، منوی توقف و مصرف حافظه تست شوند. این مرحله جایگزین تست روی دستگاه واقعی نیست.

## تصمیم فعلی پلتفرم‌ها

- **Android (فعال):** تولید پروژه، sync، ساخت دستی Debug APK و ساخت دستی Release APK/AAB امضاشده پس از تنظیم Secretهای لازم.
- **iOS (غیرفعال):** هیچ تست، شبیه‌ساز، build، runner macOS یا توسعهٔ بومی در این فاز اجرا نمی‌شود؛ فقط وابستگی و اسکریپت اختیاری برای مهاجرت آینده باقی مانده است.
- برای آغاز توسعهٔ iOS در آینده باید مجدداً به‌صورت برنچ مستقل فعال و در CI آن فاز تست شود.

## تفکیک تست‌ها

`npm test` فقط پوشهٔ `src/` را به Vitest می‌دهد؛ `npm run mobile:test` تست‌های مستقل `node:test` را اجرا می‌کند. این تفکیک خطای `No test suite found in scripts/verify-mobile.test.mjs` را رفع می‌کند و از تکرار آن جلوگیری می‌کند.

## سازگاری بومی Android

پس از هر `mobile:prepare:android`، اسکریپت `configure-android-native.mjs` تنظیمات Android Manifest، رنگ شروع برنامه، آیکون و Splash اختصاصی را مجدداً اعمال می‌کند. فونت فارسی اکنون از فایل‌های همراه برنامه تأمین می‌شود و هنگام اجرا وابستگی به Google Fonts ندارد. دکمهٔ Back اندروید به‌ترتیب پنجره‌ها، شیت‌ها و منوی توقف را کنترل می‌کند؛ در پس‌زمینه snapshot فعلی ذخیره می‌شود.

راهنمای تست دستگاه، محدودیت‌ها و آمادگی انتشار در [ANDROID_READINESS.md](ANDROID_READINESS.md) آمده است.
