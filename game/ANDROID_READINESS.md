# چک‌لیست توسعه و انتشار Android

این پروژه از Capacitor 8 و وب‌باندل آفلاین استفاده می‌کند. ساخت Debug APK و Signed APK/AAB صرفاً با اجرای **دستی** Workflowها انجام می‌شود؛ iOS در این فاز اجرا یا تست نمی‌شود.

## زیرساخت تکمیل‌شده

- یک کد مشترک وب/Android با فایل‌های داستان، تصاویر و فونت فارسی Vazirmatn Variable بسته‌بندی‌شده در خروجی.
- نمایش immersive و مخفی‌شدن کنترل Fullscreen مرورگری در نسخه Android.
- مدیریت Back برای بستن dialog، sheet و پنل منابع، سپس توقف بازی و فرستادن برنامه به پس‌زمینه.
- ذخیرهٔ محلی snapshot هنگام رفتن به پس‌زمینه. بازیابی داده بر اساس localStorage فعلی انجام می‌شود.
- تولید خودکار آیکون پایهٔ اختصاصی و صفحهٔ شروع بومی در هر بار sync، بدون وابستگی به فایل‌های Android نادیده‌گرفته‌شده توسط Git.
- ایمن‌سازی Manifest: عدم Cleartext، غیرفعال‌بودن backup خودکار، طبقه‌بندی game و مسیر Back سازگار با targetSdk=36.
- تست‌های پیکربندی Capacitor و اسکریپت‌های بومی در mobile:test؛ تست‌های وب در npm test.

## آماده‌سازی و تست محلی

از پوشه game دستورهای زیر را اجرا کنید:

```sh
npm install
npm test
npm run mobile:test
npm run mobile:prepare:android
npm run mobile:open:android
```

پیش‌نیاز: Node 22، Java 21، Android Studio و SDK API 36. برای Debug APK در بخش Actions، گردش‌کار Capacitor Android checks را با build_apk فعال دستی اجرا کنید. برای خروجی امضاشده راهنمای ANDROID_SIGNED_RELEASE.md را ببینید.

## کنترل‌های ضروری قبل از انتشار فروشگاهی

1. شناسه نهایی برنامه (فعلاً com.undergroundsurvive.game)، برند و آیکون نهایی فروشگاهی را ثابت کنید.
2. keystore اختصاصی را بسازید و پشتیبان‌گیری امن کنید؛ چهار Secret امضا را وارد کنید. versionCode باید در انتشارهای بعدی افزایش یابد.
3. APK را روی گوشی واقعی Android 7، Android 13 و Android 16 آزمایش کنید؛ به‌ویژه ناوبری ژستی، حاشیهٔ ناچ و تبلت/چرخش نمایشگر.
4. ذخیره و بازیابی پس از قفل‌شدن، پس‌زمینه، بسته‌شدن اجباری، بازگشت به بازی، تغییر زبان، صفحهٔ داستان، اتاق‌ها، زوم و صدا را تست کنید.
5. آغاز سرد برنامه، عملکرد/حافظه، خطاهای Crash/ANR و اجرا در حالت بدون اینترنت را اندازه‌گیری کنید.
6. خط‌مشی حریم خصوصی و Data Safety، تصاویر واقعی فروشگاه، رده‌بندی سنی و حساب Play Console را آماده کنید.
7. به کاربر اطلاع دهید که به‌دلیل غیرفعال‌بودن Android Auto Backup، با پاک‌کردن داده‌ها یا حذف برنامه، ذخیره محلی ممکن است از دست برود.
8. package-lock.json هنوز در مخزن ثبت نشده است. پیش از انتشار قطعی، در محیط دارای دسترسی به npm یک lockfile معتبر تولید و در Git ثبت کنید و گردش‌کارها را به npm ci تغییر دهید.
9. برای Android 16 فعلاً enableOnBackInvokedCallback=false است؛ پیش از ارتقای target SDK به 37 رفتار Predictive Back بازبینی شود.

## محدودیت تأیید

تغییر کد به معنی ساخت موفق Android یا تست روی گوشی نیست. خروجی دستی، تست دستگاه و مراحل حساب فروشگاه/کلید امضا همچنان به اقدام مالک پروژه نیاز دارند. آیکون برداری فعلی پایهٔ فنی است و می‌توان آن را پس از تصویب هویت بصری نهایی جایگزین کرد.
