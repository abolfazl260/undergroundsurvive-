# مدیریت محتوای داستان تصویری و ویدیویی

این سند مربوط به سیستم محتوای قابل‌ویرایش در GitHub است. **پیش‌درآمد رسمی بازی** در فصل `prologue-90-days` منتشر می‌شود. فصل قدیمی `demo-shelter` برای نمونهٔ فنی در مخزن نگهداری شده اما دیگر در manifest فعال نیست.

## ساختار قابل ویرایش در GitHub

```text
game/public/content/
├── manifest.json                # ترتیب فصل‌ها، زبان و نسخهٔ مجموعه
├── story/
│   ├── prologue-90-days.json    # پیش‌درآمد فارسی، شش صحنه
│   ├── prologue-90-days.en.json # نسخهٔ انگلیسی همان صحنه‌ها
│   └── demo-shelter.json        # نمونهٔ آرشیوی، در manifest نیست
└── media/
    ├── images/                   # SVG, WebP, PNG, JPEG
    ├── videos/                   # MP4 (H.264) یا WebM
    ├── posters/                  # WebP, PNG, JPEG
    └── captions/                 # WebVTT
```

افزودن/حذف/تغییر ترتیب فصل‌ها تنها با ویرایش `manifest.json` و افزودن فایل فصل انجام می‌شود. تغییر ترتیب صحنه‌ها با ترتیب آرایهٔ `scenes` است؛ کد Phaser نیاز به ویرایش ندارد.

## نمونهٔ تعریف فصل

```json
{
  "schemaVersion": 1,
  "contentVersion": 1,
  "id": "intro-one",
  "locale": "fa-IR",
  "title": "آغاز",
  "enabled": true,
  "scenes": [
    {
      "id": "opening",
      "type": "image",
      "src": "media/images/opening.webp",
      "title": "شروع",
      "text": "متن توضیح صحنه",
      "durationSeconds": 8
    },
    {
      "id": "video-one",
      "type": "video",
      "src": "media/videos/video-one.mp4",
      "poster": "media/posters/video-one.webp",
      "captions": "media/captions/video-one.vtt",
      "text": "متن در صورت بارگذاری ناموفق ویدیو"
    }
  ]
}
```

این نمونه قالب است؛ فایل‌های رسانهٔ یادشده باید جداگانه به پوشه‌های متناظر افزوده شوند. برای اضافه‌کردن فصل در `manifest.json` مورد `{"id":"intro-one","src":"story/intro-one.json"}` را به آرایهٔ `chapters` اضافه کنید. `id`ها بعد از انتشار ثابت نگه داشته شوند؛ تغییر عنوان یا `src` نیازی به تغییر `id` ندارد.

## روایت رسمی: ۹۰ روز زیر زمین

- پیش‌فرض جهان: علت آلودگی سطح زمین ناشناخته است؛ روایت نباید بدون تصمیم طراحان منشأ بحران را قطعی کند.
- دولت از طریق تلویزیون هشدار اضطراری سراسری پخش کرد. هرکس پیش از بسته‌شدن خودکار درهای پناهگاه‌ها رسید، داخل ماند.
- قفل خودکار درها تابع وضعیت بحرانی سنجش آلودگی است و سه ماه پس از آغاز قرنطینه هنوز آزاد نشده است.
- متن فارسی و انگلیسی در دو JSON مستقل است؛ هر دو همان `id`های صحنه را حفظ می‌کنند و تصاویر زبان‌خنثی‌اند.
- شش تصویر سینمایی SVG در `media/images/prologue-*.svg` نگهداری می‌شوند. عنوان‌ها، دیالوگ‌ها و شرح‌ها **داخل تصویر نیستند** و برای هر زبان از فایل JSON خوانده می‌شوند؛ می‌توان بعداً تصاویر را به WebP جایگزین کرد.
- هدف فعلی نمایش تعاملی پیش‌درآمد از دکمهٔ «داستان تصویری» در بازی است. بازشدن خودکار درها، مأموریت‌های اکتشاف و علت آلودگی موضوع فصل‌های بعدی هستند.

## قواعد ویدیو و نمایش

- برای سازگاری گسترده ویدیو را MP4 با کدک H.264 + AAC آماده کنید؛ WebM نیز پشتیبانی می‌شود. فایل ویدیو در نسخهٔ نمونه وجود ندارد و برای تست ویدیو باید یک فایل واقعی در `media/videos/` گذاشت.
- برای ویدیو پوستر اختیاری و زیرنویس WebVTT اختیاری است. کنترل پخش، توقف، صدا و نمایش زیرنویس با کنترل‌های استاندارد مرورگر ارائه می‌شود؛ autoplay عمداً خاموش است.
- اسلایدهای تصویر با «بعدی/قبلی» کنترل می‌شوند؛ `durationSeconds` اختیاری است و در صورت تعریف، به‌صورت خودکار به صحنهٔ بعدی می‌روند.
- در صورت عدم دسترسی به تصویر یا ویدیو، پوستر (اگر تعریف شده باشد) یا پیام جایگزین به همراه متن صحنه نمایش داده می‌شود. نبود رسانه نباید روند بازی را متوقف کند.
- پنجرهٔ داستان با دکمهٔ «داستان تصویری» باز می‌شود؛ با بستن/رد کردن پخش متوقف می‌شود. «رد کردن» و مشاهدهٔ فصل هیچ پاداشی ندارند.
- چیدمان در وب و موبایل یکسان و واکنش‌گراست؛ `dialog` بومی دسترسی با صفحه‌کلید و دکمهٔ Escape را فراهم می‌کند.

## اعتبارسنجی و استقرار

```bash
cd game
npm install
npm run validate:story
npm run test
npm run build
```

این اسکریپت نسخهٔ schema، عنوان، شناسه‌های یکتا، نوع صحنه، مسیرهای محلی امن، وجود فایل مدیا و تطابق شناسه/زبان manifest با فصل‌ها را بررسی می‌کند. در Pull Request بررسی خودکار `Validate story content` اجرا می‌شود.

فایل‌های محتوا از `public/content/` در بیلد Vite کپی می‌شوند و با `import.meta.env.BASE_URL` آدرس‌دهی می‌شوند؛ انتشار در زیرمسیر GitHub Pages نیز پشتیبانی می‌شود. **ویرایش GitHub بدون build/deploy خودکار باعث تغییر فوری نسخهٔ منتشرشده نمی‌شود**؛ در نسخهٔ آفلاین موبایل هم نیاز به بسته‌بندی مجدد وجود دارد. فایل‌های حجیم را بهینه کنید؛ استفاده از CDN برای ویدیوهای حجیم، با قرارداد جداگانه، قابلیت آینده است.

## پیشرفت، امنیت و مرز مسئولیت

- نشانک آخرین صحنه و وضعیت تمام‌شدن فصل در `localStorage` با کلید جداگانهٔ `underground:story-progress:v1` ذخیره می‌شود؛ به ذخیرهٔ اتاق‌ها، سکه‌ها یا مأموریت‌ها دست نمی‌زند. بعد از اتمام فصل، اجرای مجدد از ابتدای فصل ممکن است.
- محتوا عمومی است، پس اسرار، اطلاعات خصوصی، دستور اجرایی یا محاسبهٔ پاداش نباید در JSON نوشته شود. مسیر مدیا باید نسبی و داخل پوشهٔ `content` باشد.
- این برنچ موتور روایی ویدیو/تصویر است؛ زمان‌بندی مأموریت، unlock بر اساس رویداد، پرداخت پاداش و همگام‌سازی Supabase در حوزهٔ `missions` و کارهای آینده قرار دارند (Issue #3). متن یا صحنهٔ نمونه، داستان نهایی محسوب نمی‌شود.
- تغییر ناسازگار schema نیازمند ارتقای validator/reader و مهاجرت داده است؛ برای تغییرات محتوایی ساده `contentVersion` را افزایش دهید. برای بازگشت به نسخهٔ قبل از GitHub Revert و انتشار مجدد استفاده کنید.
